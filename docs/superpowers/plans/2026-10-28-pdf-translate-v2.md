# PDF 翻译技能 2.0 实施计划

> 执行方式：代理在隔离工作区完成实现；独立模块按 dispatching-parallel-agents 分工，实际翻译用独立前向验证，不向用户索要中间文件。

**Goal:** 保持五条管线边界，提高真实翻译完成率、上下文准确性和运行效率。

**Architecture:** 保留成熟构建器与适配器自有验收，修复 OCR、JPEG、可见文字路由及翻译包校验，统一术语实现并重写执行入口。

**Tech Stack:** 现有 Python、pypdf、PyMuPDF、Pillow、RapidOCR/ONNX Runtime、pytest；不升级依赖。

**Spec:** docs/superpowers/specs/2026-10-28-pdf-translate-v2-design.md

## 实施及验证

- [x] 对全部受版本管理的当前文件备份并校验；在新版分支保存含未提交改动的基线。
- [x] 运行旧版完整测试，记录实际环境失败。
- [x] OCR 模型发现/缓存/no-ocr 路径：先失败测试，再修复，再验证脚本覆盖与真实 OCR 产物。
- [x] JPEG 无损合成/最终编码证据、原子发布、透明度和源文件保护：先失败测试，再验证实际官方构建链。
- [x] 可见文字计数与可选快速路由：真实隐藏层/Form/损坏输入回归及旧新原文件计时。
- [x] 公共术语查询：首选词、别名、上下文、多义候选、词边界和原表一致性。
- [x] 原生翻译包：整页上下文、术语、重复 ID/错误类型/语言验证及原子导入行为。
- [x] 覆盖重写根、路由和五条适配器说明；核对命令与引用。
- [x] 新建实际文档翻译验证，记录产物与人工/模型真实审阅。
- [x] 新版全量测试、独立代码审查、必要修正。
- [x] 记录收益、代价和仍未证明的事项；根据证据决定是否合并，不预写胜出结论。

## 复核重点

隐藏 OCR 与可见页码混用；OCR 模型更换却命中旧缓存；不支持脚本的自信错读；JPEG 正常编码与真实图形损伤的区分；多义术语强行替换；中文目标误判残留；旧正常输出冒充当前失败预览；跨页面/单元格归属；假冒或过期审阅证据。
