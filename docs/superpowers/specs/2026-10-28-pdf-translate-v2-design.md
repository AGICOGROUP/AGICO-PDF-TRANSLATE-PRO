# PDF 翻译技能 2.0 改造设计

## 目标和边界

用户授权大幅重做现有技能，保留 native、scan、bilingual、native-cad、image 管线划分；质量、准确性、速度、容错率一起改善。用户将普通实现选择交给代理，不要求逐项设计审批。已采用独立分支 codex/pdf-translate-v2；main 在验证前不变。

当前工作状态已保存为外部压缩包及校验清单，并在 codex/pdf-translate-v2-baseline 提交中保留原有未提交代码和术语 2.0。这是比较基线；不能拿更早的 HEAD 冒充用户当前旧版。

## 保留的有效机制

- 内容路由与输出模式独立；单语替换、明确双语叠加。
- 扫描全页保底图、局部清除和可选中文字回写，不重建扫描页。
- 原生 CAD 保留矢量；源文字框、清除区域、目标排版框分离。
- 术语 2.0 的首选词、别名、语境和待复核限制。
- 原图墨迹清单、源 ID 归属、完整段落/单元格翻译、最多两次模糊文本识别。
- 同请求的哈希绑定缓存、局部修复、原子产物发布、真实语义与视觉复核。

## 选择的实现

完整替换所有执行器会引入大范围版式风险；只改文字说明又不能修复实际阻塞。采用保留稳定构建器、修复有证据的运行问题、重写入口和执行指引的方案。底层工具仍由对应适配器拥有最终验收，公共工具只处理路由、术语和诊断。

1. OCR：按实际包配置定位模型；元数据缓存；检查点包含启用模型/配置身份。unsupported script 不能静默识别为拉丁字母；明确 no-ocr 路径允许模型视觉转录及位置信息补充，未解决候选仍阻止验收。
2. 图片：JPEG 的有损编码差异通过无损合成证据和确定性最终编码复现解释，不放宽非文字损伤阈值。PNG 保持严格像素/透明通道检查。保护源文件，拒绝覆盖已有任务，修复失败时保留旧产物。
3. 路由：只统计可见原生文字，避免页码加隐藏 OCR 虚增密度；可选快速后端仍逐页检查并保留 pypdf 结构门禁。可原子保存 UTF-8 路由报告。
4. 翻译输入：双向术语查询，返回匹配别名及所有语境候选；原生翻译包携带整页上下文、目标语言和相关术语。两个导入路径共用校验，拒绝重复 ID、非字符串译文和语言错配；中文目标不再被英文残留检查误伤。
5. 指令：覆盖重写入口、路由和五条适配器说明；将具体 CAD 覆盖契约移到引用文档，消除旧双尺度强制、全局 faint 重试和不存在命令等不必要往返。真实覆盖、阅读方向和审阅要求保留。

## 验证与合并条件

先记录旧版全量测试、每个新增缺陷的失败证据，再验证修复。路由比较用实际原文件且不复用历史翻译；构建或缓存速度与完整翻译时间分开。

在新建任务中实际翻译正文/表格、扫描技术页并检查产物；补充 CAD、双语及图片的隔离运行测试。记录当前候选及源哈希、审阅和已知限制。全套测试及代码审查通过只证明实现回归，不证明全部专业翻译天然更准。

只有证据支持新版在所测范围更稳、更有效且无关键退化，才考虑合并 main；不能满足时保留候选分支并明确未验证范围。main 的既有未提交文件必须安全保留，合并前核对其与备份基线关系。
