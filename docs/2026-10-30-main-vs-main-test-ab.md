# main 与 main-test 新建任务对比测试

日期：2026-10-30。比较 GitHub main `54e6be689c3d27824f645c80c55534f567f0e719`
与 main-test `42a057f84b6676e184bd95031dd43ac40ea5597c`，不是拿本机已经含 v2 的 main 当旧版。

## 决策

本次证据支持合并：新版修复本机实际阻塞，提高可完成性与翻译输入校验，原有通过的共同测试无回退，所选实际/合成翻译样本未发现新版引入的内容或版式回退。
没有证明所有文档译文更准确、版式更好或完整任务更快；不能把局部优势表述为普遍胜出。
本次只做测试和发布，不修改构建器来让测试通过。

## 公平性与范围

- 两版使用隔离检出、相同 Python 3.14.7、依赖、字体和当前模型；不升级依赖、不修补旧分支。
- 原生样本从原始 Basic of Design.pdf 新提取第 9 页，扫描样本从原始 cand-A.pdf 新提取第 6 页。每个版本重新提取、独立翻译、构建和审阅，没有复用历史译文、OCR 或历史验收。
- JPEG 与矢量样本本次新建，明确属于合成夹具，不能代表真实大型工程图。双语与原生 CAD 使用同一新建矢量内容、各自独立流程。
- 同一任务内的局部修复保留初稿与失败记录，允许复用该任务自身已审阅译文；不将修复伪称零失败首轮通过。
- 旧版中文导入使用其文档允许的 `--allow-cjk`；缺少新路由 `--output` 时使用旧版支持的接口。不因正常旧接口差异判定翻译失败。
- 语义审阅由模型完成，主代理另看实际源图/成品；不是盲测、独立专家评审或统计准确率实验。样本有限，不推算通用完成率百分比。

## 完整回归与共同输入探针

| 检查 | main | main-test |
|---|---|---|
| 各自完整 pytest | 475 passed，7 failed，3 errors，19 subtests passed | 568 passed，24 subtests passed |
| 本次耗时 | 70.98 秒 | 66.58 秒 |
| 两边共有测试节点 | 485 个，其中 475 个原本通过 | 原本通过的 475 个全部保持通过，其余 10 个通过 |

完整测试数量不同，不能据此直接计算质量提升比例。失败和报错均与旧版写死 OCR v4 模型路径有关。本机实际配置使用 v3，新版按实际配置选择模型。

另对两版运行同一新建探针：重复 ID、null 译文、语言错配、正常英文、默认接口中文、隐藏 OCR 可见字符计数、西文 OCR 能力、俄文拒绝。旧版 1/8、新版 8/8 符合预期。这是定向缺陷回归，不是随机文件成功率；其中默认中文失败可通过旧版已支持的 `--allow-cjk` 解决，不能算旧版无法翻译中文。
俄文检查要求明确拒绝不支持的识别器；新版正确返回拒绝，绝非声称该 OCR 已支持俄文。

| JPEG，4 标签新建铭牌 | 译文/视觉检查通过，最终自动验收因 JPEG 重编码差异报 nontext changes | 译文/视觉检查通过，官方 finish 通过，具有精确合成与最终编码证据 | 修复正常 JPEG 被误拦；两版译文本身均正确 |

| 双语，新建矢量图 | 原文和译文可选，数值/否定与几何检查通过 | 同样通过 | 合成样本未发现回退 |

原生两版各发生一次语义局部修正，仍共同存在设备编码说明合段、表内对齐变化及页脚链接下划线偏移。这些是真实局限，没有将其写成版式完全相同。
JPEG 初稿两版都出现标题原文顶部残笔及字号偏小，分别作相同局部清除、源字号角色设置修正；最终文字大小与源图相近。没有把人工选参修复算成新版自动字号优势。
两版图片局部缓存重建还遇到 pypdf 解压限制，改用本任务改变样式后的正常重建完成；重复 finish 已结束的计时账本也需按已有接口继续后再验收。这些失败保留在逐域报告中，说明容错仍有改进空间。

## 时间证据与未达到事项

三份真实原 PDF 交替顺序运行三轮路由 CLI，报告内容一致。第一轮与其他验证并发，短文件出现约 0.05 秒反向差异；完整保留该轮。待重型测试结束后再完整重复三份文件，避免只挑某个好看的子结果：

| 路由输入 | main 中位秒 | main-test 中位秒 | 旧/新 |
|---|---:|---:|---:|
| 工艺总流程图，1 页 | 1.3965 | 0.8818 | 1.58 |
| Basic of Design，37 页 | 2.1717 | 1.1112 | 1.95 |
| 纯图 PDF，32 页 | 0.4047 | 0.3412 | 1.19 |

这是路由组件数据，不是完整翻译提速。并行任务、独立措辞及修复工作使两版全程计时无法作为严格速度对照。
扫描任务已知全程下限 246.09 秒，超过 180 秒，速度验收未通过；较晚启动的 168.37 秒账本不能代替全程。JPEG 包含二次字号修正和继续验收，整体也超时。不宣称扫描/图片任务已稳定达到速度上限。

“文字膨胀可增加页面”仍只是已授权的技能规则，现有固定页数构建器尚未实现自动续页；本次没有验证或发布新的自动续页引擎。

完整本地证据在 `jobs/ab-20261030/`：

两版测试命令为各自检出目录中 `python -m pytest -q --junitxml=<独立结果路径>`；定向探针接受检出路径与独立输出目录，路由基准显式使用两版脚本。
客户文档、临时图像和任务目录仅保存在本地，不提交 GitHub。扫描原始整本文件没有预运行哈希，不声称已完成其前后哈希证明；用于两版比较的新提取单页已有前后相同哈希。

合并资格依据是可复现缺陷修复、既有测试无回退和样本质量检查，而非不存在的普遍准确率或全程速度胜出证明。
