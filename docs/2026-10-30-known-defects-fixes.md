# 对比测试已知缺陷修复

日期：2026-10-30。基于已合并新版 `786438b8`，修复上轮 A/B 实际发现的问题；保留五条管线，不升级依赖、不改写扫描底图或工程图形。

## 原因与修复

| 问题 | 根因 | 实际改动 |
|---|---|---|
| 大图片译文字号明显偏小 | TSV 导入固定使用 heading 14/body 12/footer 7，而图片载体一像素对应一点 | 按源字形横向厚度、OCR 缩放及旋转计算角色基准；使用角色中位数，整段一致；显式手动样式保留，再导入只重算自身默认值 |
| 大栅格暖缓存重建失败 | 可选对象去重解压合法图像流，超过 pypdf 的 75 MB 上限 | 仅在去重触发 LimitReachedError 时丢弃可能被修改的 writer，重新从已绑定页面建立 writer，跳过去重；不提高上限、不重做 OCR |
| 损坏页面缓存导致整个任务失败 | 缓存元数据哈希正确，但 PDF 解析异常未转为缓存未命中 | 损坏页局部重建；有效页继续复用，页缓存先临时写入再替换 |
| 重复 finish 已写通过 QA 却报错 | 不检查已暂停状态，再次 pause 违反计时状态机 | 先验证计时账本，再复核真实候选；已暂停不再暂停；重建自动继续原计时，不重置起点 |
| X/AA/Y/BB/C 定义合成一段 | 流边界只识别普通编号，未识别短符号定义 | 短标识符等于文字说明建立新流；无标记的真实续行仍可合并 |
| 右侧页码左移 | footer 被视为左对齐，容器扩大到默认页边 | 从源位置识别右侧页脚，保留源右边缘 |
| 邮件下划线与译文错位 | 原矢量下划线和链接保留，但替换文字的基线、字宽改变 | 有可靠水平基线且只有一个 mailto 链接的单行页脚，将邮件逐字定位在源坐标；译后标签在安全空白中排布，保留下划线和链接矩形 |
| 表内居中的单位值变左对齐 | 多条单元格构建路径直接指定左对齐 | 在原物理单元格内按源字形边距识别居中/右对齐；近乎铺满、混合或不明确的情况保守左对齐，单元格边界不变 |

联系信息特例不会套用于多行、多链接、缺少可靠基线、有同高度文本/图片/表格障碍或手动移位的页脚。标签放不下时，在绘制任何字形前回退普通布局，并继续要求实际视觉验收。独立审查发现的多行压缩和手动移位基线两个边界回归已加测试并修复。
